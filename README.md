# china-wifi-mac

**English summary.** Give any Wi-Fi-only device (a Chinese-market car's head unit, a TV box, a gadget) a mainland-China IP through a Mac: iPhone USB tethering → macOS Internet Sharing → one `pf rdr` rule → sing-box → the Mac's own VPN (Monkey Speed in GlobalMode) or a proxy key. Confirmed once, on a Voyah Free+ (HarmonySpace 5) on 2026-10-26: the head unit's QR login, which hangs on "Loading…" from a non-Chinese IP, rendered within seconds. The script never uses `pf route-to` into a VPN tunnel — that kernel-panicked macOS 26.1 twice. Everything below is in Russian, the language of the community this was written for.

## Что это

Скрипт и инструкция: как дать устройству, которое выходит в интернет только по Wi-Fi, китайский IP, если под рукой есть Мак и iPhone. Для кого: владельцы китайских машин, у которых на экране не грузится QR-код входа в аккаунт, и вообще все, чьей приставке или гаджету нужен «домашний» китайский интернет. Windows, роутеры и Linux здесь не рассматриваются.

```
iPhone (сотовая связь) ─USB─► Mac («Общий интернет» → Wi-Fi) ─Wi-Fi─► устройство
                               └─ pf rdr → sing-box → VPN Мака (Monkey Speed, GlobalMode) → Китай
```

## Зачем устройству китайский IP

| Задача | Помогает ли китайский IP по Wi-Fi | Откуда известно |
|---|---|---|
| QR-код входа / активации на экране машины | **Да.** Без него окно висит на «Loading…» | Проверено нами 2026-10-26: сервер входа не отвечает не-китайским IP, с пекинским отвечает |
| Приложение производителя показывает данные машины | **Да** (это про телефон, а не про машину: VPN нужен на телефоне) | По отзывам владельцев |
| Скачать OTA-обновление | **Да**, с оговоркой: машина может начать качать сама, см. предупреждения | По отзывам владельцев |
| Активировать ADS / LCC (ассистенты вождения) | **Нет.** Нужна китайская сотовая сеть на модеме машины, Wi-Fi её не заменяет | По отзывам владельцев |

## Почему точка доступа телефона не помогает

Первое, что все пробуют: включить VPN на телефоне и раздать интернет с него. Не работает ни на iPhone, ни на Android без root. VPN-приложение на телефоне получает трафик только самого телефона; устройства, подключённые к точке доступа, выходят в интернет напрямую через оператора. Измерено 2026-10-26: iPhone с Monkey Speed видел себя в Пекине, а Мак, подключённый к точке доступа этого же iPhone, — в Молдове (IP оператора). Android с Monkey Speed и включённой точкой доступа — то же самое, клиент видел Молдову. Никакое другое VPN-приложение этого не меняет: так устроены сами iOS и Android.

## Что нужно

- Mac на Apple Silicon с macOS 26 (проверено на 26.1). Intel и более старые версии не проверялись.
- iPhone с режимом модема и кабель к Маку. Интернет на Мак идёт **по кабелю**, потому что Wi-Fi Мака занят раздачей.
- [Homebrew](https://brew.sh) и sing-box: `brew install sing-box`.
- Monkey Speed с оплаченной подпиской, установленный **на Мак** из App Store (раздел «Приложения для iPhone и iPad»). Это единственный проверенный способ выхода в Китай. Режим с купленным ключом есть, но не проверен — см. ниже.
- Права администратора на Маке: правило файрвола ставится через `sudo`.

```
brew install sing-box
git clone https://github.com/tolean/china-wifi-mac.git
cd china-wifi-mac
```

## Предупреждения

> ⚠️ **Никогда не направляйте трафик устройств в туннель VPN правилом `pf route-to (utunN …)`.** На macOS 26.1 это 2026-10-26 дважды закончилось kernel panic и перезагрузкой Мака. Скрипт этого не делает и не умеет; если найдёте такой совет в чате, не повторяйте.
>
> ⚠️ Пока Monkey Speed на Маке в глобальном режиме, с Мака недоступны сервисы, которые не работают из Китая (например, Claude или часть сервисов Google). Сессии в них могут слететь. Выключите GlobalMode, когда закончите.
>
> ⚠️ Машина, увидев китайский IP, может сама начать скачивать OTA-обновление. Решите заранее, готовы ли вы к обновлению прошивки.
>
> ⚠️ Через Китай идёт только TCP устройств. DNS и UDP идут напрямую. Для Voyah этого хватило; другому устройству может не хватить.
>
> ⚠️ Команда `car` выполняется с `sudo`. Правило снимается само через 15 минут и по Ctrl+C. Если что-то пошло не так: `sudo zsh car-vpn.sh off`.
>
> ⚠️ Инструмент «как есть»: используйте на свой риск и соблюдайте условия вашего VPN-провайдера и законы своей страны. Условия VPN-сервиса могут не одобрять раздачу туннеля другим устройствам.

## Шаги

1. **iPhone.** Настройки → Режим модема → «Разрешать другим» — включить. Подключите iPhone к Маку кабелем, на iPhone нажмите «Доверять».
2. **Mac, Wi-Fi.** Отключитесь от своей Wi-Fi-сети (значок Wi-Fi в строке меню → нажмите на подключённую сеть). Сам Wi-Fi не выключайте. Чтобы Мак не подключился обратно: Настройки → Wi-Fi → (…) у этой сети → выключить «Автоподключение».
3. **Mac, Общий интернет.** Настройки → Основные → Общий доступ → у пункта «Общий интернет» нажмите (i). Share from: **iPhone USB**. To devices using: **Wi-Fi**. Wi-Fi Options…: имя сети, пароль (WPA2/WPA3). Включите главный переключатель «Общий интернет» и подтвердите.
4. В Терминале: `zsh car-vpn.sh check`. Первые три пункта должны быть ✅. Пункт про VPN пока ❌ — это нормально.
5. **Monkey Speed на Маке:** GlobalMode (全局), сервер Пекин, подключить. Снова `zsh car-vpn.sh check` — теперь все пункты ✅ (у пункта «подключено устройств» допустимо ⚠️, устройство подключится на следующем шаге).
6. **Устройство.** Настройки → Wi-Fi → выберите сеть Мака, введите пароль.
7. В Терминале: `sudo zsh car-vpn.sh car`. Откройте на устройстве то, что раньше не грузилось (QR-код входа). В окне Терминала должны появиться строки `→ адрес:порт` — это соединения устройства, которые ушли через Китай.
8. Готово → Ctrl+C в Терминале, выключите GlobalMode в Monkey.

## Как понять, что работает

- `check` перед `car` показывает `Мак выходит через Китай: … 中国 北京 …`.
- После `car` в Терминале идут строки `→ …`. На Voyah Free+ среди них есть `→ 8.136.x.x:1663` — это сервер входа в аккаунт, который и не отвечал из-за границы. QR-код появляется на экране в течение ~10 секунд.
- Если строк нет вовсе — устройство не подключено к Wi-Fi Мака или ещё не открыло ничего в сети.

## Что не так

Первая колонка — сообщения команды `zsh car-vpn.sh check` и окна `car`.

| Сообщение | Что сделать |
|---|---|
| `iPhone USB: Мак не видит iPhone как сетевое устройство` | подключите iPhone кабелем, на iPhone нажмите «Доверять» |
| `iPhone USB (enN): кабель есть, но интернета нет` | iPhone: Настройки → Режим модема → «Разрешать другим» — включить; если включено — выньте и снова вставьте кабель |
| `Wi-Fi (enN) выключен` | включите Wi-Fi (но ни к какой сети не подключайтесь) |
| `Wi-Fi (enN) подключён к сети как клиент (IP x) — раздавать не может` | строка меню → Wi-Fi → нажмите на подключённую сеть, чтобы отключиться; Настройки → Wi-Fi → (…) у этой сети → выключить «Автоподключение» |
| ⚠️ `не смог определить источник «Общего интернета»` | Настройки → Основные → Общий доступ → Общий интернет (i) → Share from: iPhone USB, To: Wi-Fi |
| `«Общий интернет» берёт интернет из «X», а нужно из «iPhone USB»` | та же настройка: Share from: iPhone USB, To: Wi-Fi |
| `«Общий интернет» не работает (нет bridge100)` | сначала исправьте пункты выше, затем выключите и снова включите «Общий интернет» |
| ⚠️ `к Wi-Fi Мака пока никто не подключён` | на устройстве: Настройки → Wi-Fi → выберите сеть Мака |
| `нет sing-box` | `brew install sing-box` |
| `режим Monkey, но VPN Мака не ведёт трафик` | Monkey Speed на Маке: GlobalMode → сервер Пекин → подключить |
| ⚠️ `Мак выходит через Гонконг` | в Monkey выберите сервер Пекин (北京) — Гонконг может не подойти: для машины это другой регион |
| `Monkey подключён, но Мак выходит не через Китай` | в Monkey включите GlobalMode (全局), а не умный режим; переподключите Monkey |
| `режим с ключом, но на Маке включён VPN` | выключите Monkey/другой VPN на Маке |
| QR всё ещё крутится, хотя в окне `car` есть строки `→ …` | закройте и снова откройте окно входа на устройстве; выключите и включите Wi-Fi на устройстве |
| В окне `car`: `VPN Мака отвалился` (в журнале `missing default interface`) | туннель Monkey на Маке отвалился — так бывает; переподключите Monkey и запустите `car` снова |
| Строки `→ …` есть, но нужного сервера среди них нет и ничего не грузится | возможно, устройству нужен ещё и DNS или UDP через Китай — этот скрипт их не заворачивает; напишите issue «Проблема», приложите вывод `check` и журнал |

Журнал sing-box: `secrets/car-vpn.log`.

## Режим с ключом (не проверено)

Ключ — это строка вида `ss://…`, `ssconf://…`, `vless://…` или `trojan://…`, в которой записаны адрес прокси-сервера в Китае, порт и пароль. Такие ключи продают помесячно. Если ключ есть, Monkey Speed не нужен:

1. Положите ключ одной строкой в файл `secrets/china-key.txt` (папка создаётся рядом со скриптом, в git не попадает).
2. `zsh car-vpn.sh test` — поднимет sing-box и покажет, какой IP виден через ключ. Нужен материковый Китай (中国), не Гонконг. Сеть Мака при этом не меняется.
3. Дальше те же шаги, но Monkey на Маке **выключен**: `car` сам увидит файл с ключом и пойдёт по нему.

Этот режим не проверялся у машины: у автора нет ключа. Если проверите — напишите issue «Проверил на…». Продавцов ключей здесь не называем и не советуем.

## Как это устроено

- «Общий интернет» в macOS отправляет трафик подключённых устройств напрямую через свой источник (iPhone USB), мимо маршрута по умолчанию. Поэтому «просто включить VPN на Маке» ничего не даёт: VPN видит только трафик самого Мака.
- Единственное правило файрвола, которое ставит скрипт, — `pf rdr` на `bridge100`: TCP-соединения устройств отдаются локальному sing-box (вход `redirect` на `127.0.0.1:7892`).
- sing-box открывает новое соединение к нужному серверу уже от своего имени, как любая программа на Маке.
- Это соединение идёт по обычному маршруту Мака: через туннель Monkey Speed в глобальном режиме или, в режиме с ключом, через прокси-сервер из ключа.
- Пакеты устройства ни на каком шаге не попадают в `utun`. Именно принудительная отправка чужих пакетов в туннель (`route-to`) роняла ядро.
- DNS и UDP устройств правило не трогает, они идут напрямую. Для входа в аккаунт Voyah этого хватило: адреса серверов из любой страны разрешаются одинаково, а сам вход идёт по TCP.

Команды: `check` — диагностика цепочки; `test` — проверка ключа (только режим с ключом); `car` — завернуть трафик (с `sudo`, автостоп 15 минут); `off` — аварийно снять правило и остановить sing-box.
